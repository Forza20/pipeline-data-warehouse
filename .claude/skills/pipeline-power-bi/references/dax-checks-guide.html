How to use checks.dax and grounded-answers.dax

Two files from your pipeline-power-bi run that prove the Power BI model gives the same numbers as your source files.

What the files are

FileWhat it provesColumns in the result
checks.daxThe totals are right: row counts, every headline measure, keys without a match, test rows left.Check · In Power BI · Expected · Difference
grounded-answers.daxReal business questions get the right number, also for a user with a security role (RLS).No · Question · Value · Expected · Difference

The Expected numbers were computed from your source files, not from the model. So a Difference of 0 means the model and the files agree.

Both files are in the run folder: runs/<run-id>/. Next to them you find expected-values.md and grounded-answers.md, which say how each expected number was computed.

Before you start

  1. Open runs/<run-id>/pbip/<Name>.pbip in Power BI Desktop.
  2. Click Home → Refresh. If Power BI asks for access to the data folder, approve it.
  3. Wait until the refresh is done. The checks read the loaded data, so an empty model gives wrong results.

Run checks.dax

  1. Open checks.dax in Notepad or VS Code. Select all text and copy it.
  2. In Power BI Desktop, click DAX query view in the left bar (the icon below the model view).
  3. Paste the text into the query editor.
  4. Click Run (or press F5).
  5. Read the result table. You get one row per check.

The file looks like this:

EVALUATE
VAR Checks =
    {
        ( "Rows Sales", COUNTROWS ( Sales ), 200 ),
        ( "Total sales", [Total sales], 526643.91 ),
        ( "Test rows left (Customer 9999)", COUNTROWS ( FILTER ( ... ) ), 0 )
    }
RETURN
    SELECTCOLUMNS ( Checks, "Check", [Value1], "In Power BI", [Value2],
        "Expected", [Value3], "Difference", ROUND ( [Value2] - [Value3], 2 ) )
Pass: every value in the Difference column is 0. The model matches the source files.

Write the numbers into the column "In Power BI" in expected-values.md if you want a record of the check.

Run grounded-answers.dax

This file holds 3–5 business questions, for example "Sales in region North in March 2025". Each question uses a measure with filters, the way a report user would ask it.

  1. Open a new query tab in DAX query view (the + next to the tab names).
  2. Copy all text from grounded-answers.dax, paste it and click Run.
  3. Read the result: one row per question, and one extra row per role check.
  4. Open grounded-answers.md. For each question, fill in the line "In Power BI" with the Value from the result.

grounded-answers.md also tells you, per question, the measure's DAX formula, the measures and columns it uses, and the source file or sheet and column of each. Use it when you want to know where a number comes from.

Pass: every Difference is 0, and the role rows are confirmed (next section).

Check the role rows

A row with "– as <role> (<user>)" in the Question column tests what that user may see. DAX query view does not apply security roles, so the file simulates the role in DAX. Confirm it once in the real role:

  1. Go to Modeling → View as.
  2. Tick the role, tick Other user and type the user name from the row (for example anna@example.com).
  3. Click OK. Look at the card or visual with the measure from the question.
  4. The number must be the same as the Expected value in the role row. Then click Stop viewing.
If the model has no security roles, the file has no role rows. Skip this section.

When a Difference is not 0

  1. Look up the check or question in expected-values.md or grounded-answers.md. Read how the expected number was computed.
  2. Ask: does a cleaning choice explain it? For example, a removed duplicate row (F12) or flagged amounts (F14) change totals. F-codes are the IDs of the cleaning steps; each Power Query step carries its F-code in its name.
  3. If a choice explains it, write the reason next to the number. If not, the model must be fixed.
  4. To fix, run /pipeline-power-bi --resume <run-id> and say which check failed. The skill finds the cause, rebuilds and writes new files.
  5. Refresh in Power BI Desktop and run both files again.
An error instead of a result? The error message often names a Power Query step, for example F08 Parse order_date. Tell the skill the step name, or open Transform data and look at that step under Applied steps.

Run the checks again

Run both files after every refresh with new source files and after every change to a measure. A rebuild writes new versions of both files, so always use the newest ones from the run folder.
